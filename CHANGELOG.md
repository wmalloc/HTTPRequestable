# Changelog

All notable changes to this project will be documented in this file.

## [1.0.0]

### Added
- **HTTPContentType(pathExtension:)**: The content type for a file name extension, such as `image/png` for `png`, ignoring case. Common extensions come from a built-in table, so they are the same on every platform; others are looked up with `UTType` where it is available. Returns `nil` for unknown extensions.
- **HTTPContentType** constants: `csv`, `heic`, `javascript`, `m4a`, `mp3`, `mp4`, `pdf`, `quickTime`, `webp` and `zip`.
- **HTTPRequestConfigurable.validateResponse(_:)**: Checks a response before `object(for:)` decodes it. The default accepts only `2xx` statuses; implement it to accept other statuses, check the content type with `HTTPClientResponse.validate()`, or throw your own error decoded from the response body.

### Fixed
- **MultipartForm** checked `streamError` after every read and write, which crashed on Linux, where Foundation traps when `streamError` is read. It now checks for an error only when a read or write fails, that is, returns `-1`, as Foundation documents. The failure carries the stream's `streamError` on Apple platforms and a generic error on Linux.
- **Linux**: Every file imported either `FoundationNetworking` or `Foundation`, never both, and `FoundationNetworking` does not re-export `Foundation`, so types such as `URLComponents` were missing on Linux. Files now always import `Foundation` and add `FoundationNetworking` where it exists. `HTTPTypesFoundation` is now imported, and re-exported by `HTTPRequestable`, on every platform rather than only Apple's. APIs that Foundation provides only on Apple platforms are now limited to them: `bytes(for:delegate:)` on `HTTPTransportable`, `HTTPTransferable` and `URLSession` (it needs `URLSession.AsyncBytes`), and the `URLRequest` setters `setAttribution(_:)`, `setAllowsConstrainedNetworkAccess(_:)`, `setAllowsExpensiveNetworkAccess(_:)` and `setAssumesHTTP3Capable(_:)`, whose properties Foundation on Linux does not have. `MultipartForm` checks that a file is reachable with `checkResourceIsReachable()` where `checkPromisedItemIsReachable()` is unavailable. `MockURLProtocol` is `Sendable` only on Apple platforms, because Foundation on Linux makes `URLProtocol`'s `Sendable` conformance unavailable; its loading task no longer captures `self`, so it compiles there.
- **URLRequest.headerFields**, **setHttpHeaderFields(_:)** and **setHeaders(_:)**: Replacing or clearing the headers left the existing ones in place, because assigning `URLRequest.allHTTPHeaderFields` only adds and overwrites fields. For example, `setHttpHeaderFields(nil)` kept an `Authorization` header it was documented to remove. They now remove the existing fields first.
- **URLRequest.setHttpBody(_:contentType:)**: Setting the body to `nil` kept the previous `Content-Length`; it is now removed with the body.
- **MultipartForm**: The file imported `CoreServices`, `OSLog` and `UniformTypeIdentifiers` without checking they exist, so the package could not build where they are missing, such as on Linux. `OSLog` and `CoreServices` were unused and are removed; file MIME types now come from `HTTPContentType(pathExtension:)`, which uses `UTType` only where `UniformTypeIdentifiers` exists. Uploaded `.m4a` files are now sent as the registered `audio/mp4` instead of Apple's `audio/x-m4a`.

### Changed
- **URLRequest.setHttpShouldUsePipelining(_:)** is deprecated, following Foundation, which deprecates `httpShouldUsePipelining` on every platform (from macOS 15.4 and iOS 18.4 on Apple platforms, where it only affects the classic URL loader). Adopt HTTP/2 or HTTP/3 instead.
- **Error messages** for `HTTPError` and `MultipartFormError` are no longer localized. Their English text is built in, so the package no longer ships a string catalog or declares resources, and messages are the same on every platform, including Linux, where `String(localized:bundle:)` is unavailable. `HTTPError.headerValueMissing` now includes the header name, as in `Header missing value: mockIdentifier`; it was dropped before.
- **Breaking — URLRequest builder**: Removed the `String` versions that duplicated typed ones: `setHttpMethod(_: String?)` (use `setMethod(_:)`), `setHttpHeader(_:forName:)` and `addHttpHeader(_:forName:)` (use the `forField:` versions or `setHeader(_:)`/`addHeader(_:)`), `setHttpHeaders(_: [String: String])` (use `setHttpHeaderFields(_:)` or `setHeaders(_:)`), and `setHttpBody(_:contentType: String?)` and `setContentType(_: String)` (use the `HTTPContentType` versions; string literals still work). Renamed `setMaindocumentURL(_:)` to `setMainDocumentURL(_:)` and `setAllowsConstraintNetworkAccess(_:)` to `setAllowsConstrainedNetworkAccess(_:)`, matching the `URLRequest` properties. No deprecated aliases remain.
- **@frozen** is removed from `HTTPContentType`, `RetryPolicy`, `KeyedItem`, `Quality`, `Quality.Item` and `Quality.Parameter`. It only matters for binary frameworks built with library evolution, which this package is not, so builds are unaffected.
- **Sendable**: `HTTPRequestHeadersModifier`, `HTTPRedirectPolicy` and `HTTPSecurityDelegate` are now checked `Sendable` instead of `@unchecked Sendable`, so the compiler verifies they hold no mutable state. `MockURLProtocol` stays `@unchecked`, because `URLProtocol` is not `Sendable`; the reason is now documented.
- **Sample**: Removed `ServerTrustEvaluator` from HackerNewsKit. It was `@unchecked Sendable` with a mutable flag, accepted any certificate when pinning was turned off, and was not used by the app. `HackerNews` now sends every request with an optional `requestDelegate`, and `HackerNews(pinning:)` shows public key pinning with `HTTPPublicKeyPinning` and `HTTPSecurityDelegate`.
- **Breaking — object(for:)** on `HTTPTransferable` and `URLSession` now throws `HTTPError.unacceptableStatusCode` for a status outside `2xx`, through the request's `validateResponse(_:)`. A `404` or `500` body was previously passed to the response transformer: `Decodable` results failed with a misleading decoding error, and `Data` or `String` results returned the error page as if it succeeded. This includes the last response after `RetryPolicy` retries are used up. Requests that relied on decoding non-`2xx` bodies must implement `validateResponse(_:)`.
- **Empty responses**: `HTTPClientResponse.transformed(using:)` no longer throws `URLError(.zeroByteResource)` for an empty body; it passes empty `Data` to the transformer. A `Void` result now succeeds for `204 No Content`, and `Data` and `String` results can be empty. The default `Decodable` transformer still throws `URLError(.zeroByteResource)` for an empty body. Custom transformers can now be called with empty `Data`.

## [0.90.0]

### Added
- **RetryPolicy.retryableStatuses**: Responses with a retryable status are now retried, by default `429 Too Many Requests` and `503 Service Unavailable`. A `Retry-After` header, in seconds or as an HTTP date in any of the three RFC 9110 formats, lengthens the backoff delay; one longer than `maxDelay` ends the retries. When the retries are used up, the last response is returned for the caller to validate. Pass `retryableStatuses: []` to retry network errors only. The new `shouldRetry(status:attempt:)` exposes the check.
- **RetryPolicy.jitter**: Backoff delays are now randomized between half the computed delay and all of it by default ("equal jitter"), so clients that failed together do not retry together and no wait is zero. Pass `jitter: false` for the exact delays. `delay(for:)` still returns the delay without jitter.
- **RetryPolicy.default** is now public, and `RetryPolicy` is explicitly `Sendable`.
- **#URL**: Expression macro that turns a string literal into a `URL` checked when you build: `let base = #URL("https://api.example.com/v1")`. The build fails unless the literal is a valid URL with a scheme and a host, written without interpolation, with characters such as spaces already percent-encoded, and without a user name or password. It expands to `URL(string:)!`, which cannot fail because only literals every Foundation version parses the same way are accepted.
- **#HTTPFieldName**: Expression macro that turns a string literal into an `HTTPField.Name` checked when you build: `static let requestID = #HTTPFieldName("X-Request-ID")`. The build fails unless the literal is a valid RFC 9110 field name written without interpolation, so names with spaces, colons, line breaks or non-ASCII characters, and pseudo header fields such as `:authority`, are rejected. It expands to `HTTPField.Name(_:)!`, which cannot fail because the macro runs the same check.
- **HTTPRequestConfigurable.pathComponents**: Path segments that are percent-encoded one by one, so a `/` in a value is sent as `%2F` instead of adding segments: `var pathComponents: [String] { ["files", fileName] }`. The default implementation splits `path` on `/`, so existing requests are unchanged.
- **HTTPSecurityDelegate**: Task delegate that applies the redirect policy, optional public key pinning and an optional response size limit, and forwards every other callback to a wrapped delegate. Delegates passed to requests are now wrapped in it automatically, so passing one no longer disables redirect protection.
- **HTTPPublicKeyPinning**: Pins by base64 SHA-256 of `SubjectPublicKeyInfo` (the openssl/HPKP format), with backup pins, per-host scoping and optional subdomains. The system validates the chain before pins are checked.
- **Response size limit**: `HTTPSecurityDelegate(maxResponseSize:)` makes `performRequest` stop reading and throw `URLError(.dataLengthExceedsMaximum)` once a response exceeds the limit.

### Fixed
- **HTTPTransferable.retryPolicy**: The default of no retries was internal, so types conforming to `HTTPTransferable` outside the module had to declare `retryPolicy` or failed to compile, including the README example. The default is now public.
- **RetryPolicy**: A very large `maxDelay`, such as `.greatestFiniteMagnitude`, crashed the retry loop, because `Task.sleep` cannot represent durations beyond about 1.7×10²⁰ seconds. Delays are now also capped at `RetryPolicy.longestDelay` (10⁹ seconds). The `maxRetries` documentation said "tries"; it counts retries, so a request is sent at most `maxRetries + 1` times.
- **HTTPClientResponse.validate()** and **validateContentTypes(_:)**: Valid responses were rejected because content types were compared as exact strings. `application/json` now accepts `application/json; charset=utf-8` and `Application/JSON`, `text/*` accepts any `text` subtype, and `*/*;q=0.1` in `Accept` accepts anything. A `Content-Type` that is not a valid media type throws `HTTPError.invalidContentType`.
- **HTTPRequest.acceptContentTypes**: `q` parameters were kept in each value, so no range with a `q` ever matched, and `q=0` (not acceptable) was ignored. Ranges are now returned without parameters, entries with `q=0` or an invalid `q` are left out, and commas inside quoted values no longer split an entry. When the header is set but no entry is acceptable, the set is empty rather than `nil`, so nothing is accepted instead of everything.
- **HTTPResponse.contentTypes**: `Content-Type` was split on commas, so `text/plain; a="x,y"` became two broken values. It is now parsed as the single media type it holds. The new `HTTPResponse.contentType` returns it directly.
- **KeyedItem.encoded**: Parameter values that are not tokens are now quoted, with `"` and `\` escaped, so a value such as `a.txt; evil=1` can no longer add parameters. Values that are already quoted-strings are kept. Parameters are sorted by key, so the output no longer changes between launches, and an item without parameters is written without a trailing `; `.
- **Quality.encoded**: q-values are written with at most three decimals and no exponent, so a value such as `0.00001` is no longer sent as `q=1e-05`.
- **Quality(values:)**: With more than ten values the q-value went to `0` (not acceptable) and then below it. The step now shrinks with the number of values, so every value stays above `0`.
- **MultipartForm**: `Content-Disposition` `name` and `filename` values now percent-encode every control character, not only CR and LF.
- **HTTPTransferable**: `upload(for:from:)`, `upload(for:fromFile:)`, `upload(for:multipartForm:)` and `download(for:)` now apply `HTTPSecurityDelegate`. They previously passed the delegate to `URLSession` unwrapped, so redirects were followed with no redirect policy: credentials went along on cross-origin redirects, https→http redirects were followed, and pinning was skipped.
- **HTTPInterceptor**: Documentation said interceptors run in reverse order. The first interceptor is the outermost: it sees the request first and the response last.
- **HTTPInterceptor**: An interceptor that passed a different delegate to `next` replaced the caller's, which dropped the caller's public key pins and response size limit, and a delegate with no redirect policy turned redirect protection off. The caller's redirect policy, pins and size limit now always apply; the interceptor's delegate receives the remaining callbacks and can only add restrictions (the smaller size limit wins). Platforms without the Objective-C runtime are unchanged.
- **README**: Removed the claim that logging interceptors are provided; none are. Added guidance on keeping credentials out of logs.
- **HTTPRequestConfigurable.url**: An environment without a scheme (for example `HTTPEnvironment(string: "api.example.com/v1")`, which parses as a path) crashed in `HTTPRequest(url:)` with "Schemeless URL is not supported". `url` now throws `HTTPError.invalidURL` when the scheme or host is missing. `String` and `URLComponents` conversions to `HTTPRequest` throw `URLError(.badURL)` in the same cases.
- **HTTPRequestConfigurable.url**: A percent-encoded query on the environment was decoded and re-encoded, so `sig=abc%2Bdef` was sent as `sig=abc+def`. It is now kept exactly, and request query items are appended after it. `HTTPEnvironment.appendQueryItems` keeps the existing query the same way.
- **HTTPRequestConfigurable.url**: A percent-encoded `/` in the environment path (`%2F`) was decoded into a separator. The environment path is now kept as it is encoded.

### Changed
- **Breaking — RetryPolicy(…)** checks its configuration: `maxRetries` and `multiplier` must be `0` or more (and `multiplier` finite), and `initialDelay` and `maxDelay` must be finite and more than `0`. Invalid values now stop the process with a precondition failure. They were accepted before and produced zero delays (a negative multiplier or zero initial delay), a delay of `maxDelay` (a NaN initial delay) or a crash (an infinite `maxDelay`). Every wait is now more than zero: the delay never falls below `initialDelay`, so a multiplier of `1` or less gives a fixed delay; jitter picks between half the delay and all of it; and a `Retry-After` shorter than the backoff delay, including `0`, waits the backoff delay.
- **Breaking — HTTPContentType** validates its input. `init?(rawValue:)` is now failable and returns `nil` unless the value is a media type: `type/subtype` followed by `; name=value` parameters, with tokens for names, types and subtypes, and tokens or quoted-strings for values. Values containing control characters, spaces outside quotes or a repeated parameter are rejected. `init?(_:)` now returns `nil` for invalid values, decoding throws `DecodingError.dataCorrupted`, and an invalid string literal stops the process with a precondition failure. The new `type`, `subtype` and `parameters` properties hold the parsed parts, `mimeType` is now lowercased, and equality ignores the case of the type, subtype, parameter names and the `charset` value. The new `matches(_:)` checks whether a content type is in a media range such as `text/*`. `contentTypes(for:)` now splits only on commas outside quotes and leaves out invalid entries. `HTTPContentType.formData` is removed: `form-data` is a `Content-Disposition` value, not a media type.
- **Breaking — MockURLProtocol** identifiers are renamed from "test" to "mock". The old names are removed, without deprecated aliases:
  - The `TestIdentifiable` protocol is now `MockRequestKey`, which says what it is: the key `MockURLProtocol` uses to find the handler for a request. Its requirement `testIdentifier` is now `mockIdentifier`, so conforming types must rename that property.
  - The header is now `X-Mock-Identifier` instead of `X-Test-Identifier`. Code or server fixtures that set or match `X-Test-Identifier` by its literal name must use the new name.
  - `HTTPField.Name.xTestIdentifier`, `String.xTestIdentifier`, `HTTPRequestConfigurable.byAddingTestIdentifierHeader()` and `HTTPRequestConfigurable.testIdentifier` are now `xMockIdentifier`, `xMockIdentifier`, `byAddingMockIdentifierHeader()` and `mockIdentifier`.
- **Breaking — KeyedItem** validates its input and throws the new `HTTPFieldValueError`. `init(item:parameters:)` now `throws` and rejects an item that is not a token or a media range, a parameter name that is not a token, and a parameter value containing a control character such as CR or LF. `parameters` is now `private(set)` and the subscript is get-only; set parameters with the throwing `setParameter(_:forKey:)`. Previously these values were written as given and could produce invalid or injected header values.
- **Breaking — Quality** validates its input and throws `HTTPFieldValueError`. `Quality.Item.init(item:parameters:)`, `Quality.Parameter.init(q:)`, `Quality.Parameter.init(double:)` and `Quality(values:)` now `throw`. Items must be tokens or media ranges, and q-values must be in `0...1` (NaN is rejected). Decoding `Quality.Item` and `Quality.Parameter` validates the same way. Float and string literals for `Quality.Parameter` stop the process with a precondition failure when they are not a number in `0...1`; the string literal `"abc"` previously meant no q-value. `Quality.Item.init` now defaults `parameters` to `nil`, and `KeyedItem.init` defaults `parameters` to `[:]`.
- **MultipartForm(boundary:)**: The boundary must now be 1 to 70 RFC 2046 characters, not ending with a space; an invalid boundary stops the process with a precondition failure. A boundary containing CR or LF was written differently in the `Content-Type` header and in the body, so the server could not split the body. The default UUID boundary is unaffected.
- **MockURLProtocol.setRequestHandler(_:forRequest:)**: A request without an `X-Mock-Identifier` header now registers its handler under the request's URL, which is how a sent request without the header is looked up. It previously threw `URLError(.badURL)`, so such requests could only be stubbed with `setRequestHandler(_:forIdentifier:)`. It still throws when the request has neither the header nor a valid URL.
- **HTTPInterceptor**: When an interceptor moves a request to another origin, sensitive header values the request carried into the chain (for example an `Authorization` header added by a request modifier) are removed; values the interceptor sets itself are kept. Moving an `https` request to another scheme throws `URLError(.appTransportSecurityRequiresSecureConnection)`. Both follow the redirect policy of the caller's delegate, and a delegate substituted by an interceptor cannot relax them.
- **HTTPTransferable**: `bytes(for:)` now applies `requestModifiers`, like every other request method. Interceptors still do not run for streamed requests, and this is now documented.
- **HTTPRequestConfigurable.url**: Path segments of `.` or `..`, including percent-encoded ones, now throw `HTTPError.invalidURL`. Servers and proxies resolve them, so a value such as `"../admin"` interpolated into `path` could reach a different endpoint.
- **HTTPRequestConfigurable.url** and **HTTPEnvironment.setQueryItems / appendQueryItems**: `+` in query names and values is now sent as `%2B` (and `;` as `%3B`). It was sent as is, and servers decode `+` as a space, which broke values such as emails, phone numbers and signatures.
- **HTTPRequestConfigurable.url**: A user name or password on the environment is now removed from `url`. They were never sent (`HTTPRequest` keeps only the scheme, host and port), so keeping them in `url` only exposed credentials wherever the URL was logged.
- **HTTPEnvironment**: Deprecated `setUser(_:)`, `setPassword(_:)`, `setPercentEncodedUser(_:)` and `setPercentEncodedPassword(_:)`. Credentials set this way were silently not sent; use an `Authorization` header instead.
- **Breaking — HTTPInterceptor.NextHandler** is now `@Sendable`, so interceptors can call `next` from child tasks (for example to race a request against a timeout). Existing `HTTPInterceptor` conformances compile and behave unchanged, including ones that spell out the closure type without `@Sendable`. Code that creates a `NextHandler` closure, for example to call `URLSession.performRequest(_:next:interceptors:delegate:)` or an interceptor directly, must make it `@Sendable`, so it can no longer capture non-`Sendable` values.

## [0.80.0]

### Fixed
- **HTTPContentType**: Fixed whitespace handling during decoding by using the existing `init(rawValue:)` logic.
- **HTTPRequestConfigurable**: Made `path` property non-optional and updated its default implementation.
- **HTTPRequestConfigurable**: Fixed compilation error in `url` property caused by non-optional `path`.
- **Package.swift**: Excluded `README.md` and `LICENSE` from the `HTTPRequestable` target to prevent them from being processed as resources.

### Changed
- **HTTPContentType**: Removed string-literal equality operator for more predictable behavior.
- **HTTPRequestableMacrosTests**: Added unit tests for macro expansions.
